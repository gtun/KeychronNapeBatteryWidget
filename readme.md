A small system tray widget that shows the battery level of the **Keychron Nape Pro** trackball.
It is based on [MrAdrianPl/keychron_battery_widget](https://github.com/MrAdrianPl/keychron_battery_widget), which does the same for the Keychron M5.

- Works over the **Keychron Link-KM 2.4 GHz receiver** (`3434:d026`) and a **USB cable** (`3434:0440`).
  If both are connected, the cable is used.
- The tray icon shows the percentage as large digits above a level bar, drawn natively at each tray size so it stays readable at 16 px. The bar turns amber at 30%, the digits and bar turn red at 15%, and both are green while charging. Use `--no-text` for a battery outline and `--theme dark|light` if your panel colour is detected wrongly.
- Sends a desktop notification once when the battery drops to 15% or below.
- Re-reads every 5 minutes. Left-click the icon or choose **Refresh now** to read it immediately.
- While the Nape is asleep, the icon fades and the tooltip shows the last reading and when it was taken.
- Follows the desktop light/dark theme.
- Bluetooth is not supported. Over Bluetooth, the OS usually shows the battery itself through the standard BLE Battery Service.

Should work on any desktop that has a system tray.

## How it works

The Nape Pro runs Keychron's ZMK-based firmware. Unlike the M5, it does not use the `b3 06` request on interface 4.
It exposes a VIA-style Raw HID collection (usage page `0xFF60`, usage `0x61`) that takes 32-byte packets. The Link-KM receiver exposes the same collection and forwards the packets to the trackball.

```
request : 00 | a7 31 00 00 ... (32 bytes)     leading 00 = HID report ID
reply   :      a7 31 <percent> <charging> ...
```

Over the receiver, the widget first sends `b2` to check whether the Nape (`3434:4004`) is connected in a receiver slot.
Replies that don't match the request, such as layer-change (`a3`) and receiver (`bc`) notifications, are skipped.

The protocol comes from the reverse-engineering work in [nvalis/nape_pro](https://github.com/nvalis/nape_pro) and [ky0209/NapeBar](https://github.com/ky0209/NapeBar).

## Running from source (Linux)

```sh
sudo apt install libhidapi-hidraw0          # Fedora: hidapi, Arch: hidapi
python3 -m pip install -r requirements.txt  # PyQt6 >= 6.5, hid
python3 src/nape_widget.py                  # --interval 120, --no-text
```

To check the connection without the GUI:

```sh
python3 src/nape_battery.py
# BatteryReading(status=<Status.OK: 'ok'>, connection=<Connection.WIRELESS: 'wireless'>, percent=87, charging=False, detail='')
```

### Device permissions

By default, regular users can't open `/dev/hidraw*`. Install the included udev rule, then replug the receiver or cable:

```sh
sudo cp udev/99-keychron-nape.rules /etc/udev/rules.d/
sudo udevadm control --reload-rules && sudo udevadm trigger
```

Without the rule, the tooltip shows *"No permission to open the device"*.

### Autostart

Copy a desktop entry into `~/.config/autostart/`:

```ini
[Desktop Entry]
Type=Application
Name=Keychron Nape battery
Exec=python3 /path/to/src/nape_widget.py
```

### AppImage

No AppImage is published. To build one yourself with [appimage-builder](https://github.com/AppImageCrafters/appimage-builder):

```sh
python3 -m pip install --prefix=/usr --root=AppDir -r requirements.txt
appimage-builder --recipe build-scripts/AppImageBuilder.yml
```

## Windows

No exe is published. Build it yourself (needs Python 3.10+):

```powershell
powershell -ExecutionPolicy Bypass -File .\build-scripts\build_windows.ps1
# -> dist\KeychronNapeBatteryWidget.exe
```

The script installs the dependencies and PyInstaller into `.venv-win`, downloads `hidapi.dll` from the [hidapi releases](https://github.com/libusb/hidapi/releases), and bundles everything into one portable file: once built, it needs no Python, drivers or admin rights.

- The icon may start in the hidden tray area (the `^` arrow). To keep it visible, drag it onto the taskbar.
- To start it at login, right-click the icon and choose **Start automatically at login**. This adds an entry under `HKCU\...\CurrentVersion\Run` that points at the exe's current location, so move the exe to its permanent folder first.
- SmartScreen may warn that the exe is unsigned. Choose **More info → Run anyway**.

To run from source instead, install the requirements and put `hidapi.dll` (x64) next to `src/nape_battery.py`.

## Corsair Vanguard 96 keyboard screen

The battery level can also be shown on the 320×170 screen of a **Corsair Vanguard 96 / Vanguard Pro 96** keyboard.

iCUE's built-in screen options only take images, but iCUE 5.47 and later can also run custom **HTML widgets** on the keyboard screen (device type `keyboard_lcd`).
A widget runs inside iCUE's embedded browser, so it can't open the Nape over HID itself. Instead, the tray app serves the reading on `localhost`, and the widget polls it:

```
Nape Pro ──HID──> tray app (nape_bridge.py) ──http://localhost:47815/battery──> iCUE widget ──> Vanguard screen
```

The tray app only listens on `127.0.0.1`, only answers `GET /battery`, and rejects requests whose `Host` isn't a loopback name.

**Setup (Windows):**

1. Run the tray app, right-click its icon and turn on **Show on Corsair Vanguard screen** (or start it with `--vanguard`). The choice is remembered.
   On Windows Firewall, no inbound rule is needed: the port is loopback-only.
2. Package the widget with Corsair's Widget Builder CLI (needs Node.js):
   ```powershell
   npm install -g icuewidget-cli
   icuewidget validate vanguard-widget\NapeProBattery
   icuewidget package vanguard-widget\NapeProBattery
   ```
3. In iCUE (5.47 or later), open the keyboard, go to the **Widgets** list, click **+** and pick the `.icuewidget` file (or double-click it). Accept the `localhost:47815` network permission it asks for.
4. Add **Nape Pro Battery** to the screen. Switch screen widgets with **FN + ←/→** or the dial (set the dial to *Screen Widget* in the Rotary Dial tab).

The widget shows the percentage, a level bar in the same colours as the tray icon, the connection (USB or 2.4 GHz) and a bolt while charging.
While the Nape sleeps it keeps the last level, faded, with the time it was read. If the tray app isn't running, it says so.

Limits from iCUE: widgets only run while iCUE is open and the keyboard is connected by USB cable, and they can't be saved to the keyboard's hardware mode.

Without the tray icon, the bridge can also run on its own: `python src/nape_bridge.py`.

### Without iCUE (experimental)

The tray app can also draw on the screen directly, so neither iCUE nor Web Hub has to run. The keyboard shows images from its own onboard memory, the ones Corsair Web Hub uploads. The app overwrites one of those images with the battery picture, and the screen redraws at once.

> [!CAUTION]
> This uses an **undocumented, reverse-engineered protocol** (see [src/vanguard_screen.py](src/vanguard_screen.py)). It is only tested on one wired Vanguard Pro 96 (`1b1c:2b0e`). Each redraw writes to the keyboard's flash memory. A bad write could leave the screen blank until you upload an image again with Web Hub or iCUE.

1. With iCUE closed, open [Corsair Web Hub](https://www.corsair.com/web-hub/index.html) in Chrome or Edge. Upload any 248×170 image on the keyboard's **Screen** page, then close the tab.
2. In the tray menu, turn on **Draw on Corsair Vanguard screen (no iCUE)**. The app takes the newest screen image and draws over it. The other images stay as they are.
3. Switch to that image with **FN + ←/→**.

To limit flash writes, the app redraws only when the level moves by 5% or more, crosses 30% or 15%, reaches 100%, or charging starts or stops. While the Nape sleeps, the screen keeps the last picture. The keyboard must be connected by USB cable. Don't run iCUE at the same time, because both would talk to the keyboard.

`python src/vanguard_screen.py list` shows the screen's images without changing anything.

## Known firmware quirk

The Nape firmware sends a notification on the Raw HID interface whenever the layer changes. Some reports say that on Linux, if nothing reads these notifications, the trackball's USB stack can hang until it is replugged. This widget opens the interface only briefly when it polls. If you see this hang, see [this workaround](https://github.com/youknowcast/ykc-omarchy-setup-kit/pull/3).
